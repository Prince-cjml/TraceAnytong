# Acceptance

The initial product accepts immutable source versions, issues anonymous personalized copies, creates bounded web sessions, preserves evidence, and returns explainable candidate ranking.

- `traceHandle` is opaque; `wmCode` uniquely maps to one trace identity.
- Duplicate job keys are idempotent; expired leases are recoverable.
- JPEG, PNG, WebP, PDF, DOCX and PPTX adapters reject unsupported inputs with typed errors and preserve valid native artifacts where supported.
- Watermark layer is fixed, uses `pointer-events: none`, and does not continuously animate.
- Trace results expose watermark, margin, fingerprint, geometric, structure and timeline evidence; unwatermarked or ambiguous input is never falsely attributed.
- Benchmark reports are deterministic and include attack and negative results.
- Public API authorization is centralized before storage download URLs are returned.

## Orchestrator-review public interface changes

- `devBootstrap:bootstrap` and `devBootstrap:cleanup` are development-only administrative mutations. They require both `DEV_BOOTSTRAP_ENVIRONMENT=development` and the exact server-side `DEV_BOOTSTRAP_SECRET`; neither variable may be configured in production. Bootstrap is deterministic and idempotent, while cleanup is idempotent and refuses to remove an organization that contains non-fixture work.
- Worker candidate submission now requires exactly one server-resolved issuance or web-session provenance binding. The service validates that binding, the opaque trace handle, immutable profile/protocol versions, raw evidence, score bounds, and profile-owned attribution thresholds before accepting a decision. Worker-supplied thresholds are not trusted.
- Worker job input now includes immutable `profileVersion` and the issuance timestamp as `createdAt`, so the `TraceIdentity` sent to a worker can be reconstructed without recipient identity data.
- `traceCases:list` is investigator/admin-only and uses a bounded opaque cursor. A web-session tile download is authorized for the session recipient (or an administrator) after organization membership is checked. Session tile storage may be bound only through leased `jobs:complete`; there is no separate worker-token-only tile-finalization write path, and browser responses never include profile keys or derivation inputs.
- A trace case now selects an immutable profile and atomically queues a bounded `trace` job. Its leased worker input contains only the evidence URL plus at most 100 ready, same-profile anonymous candidate bindings: issuance candidates carry opaque trace handle, issuance timestamp, optional server-mapped code, and derived hash; screen candidates carry opaque trace handle and session timestamp. It contains no recipient identity. A candidate is recorded only after detector evidence matches one of those server-resolved bindings.
- Screen-profile trace jobs receive the immutable carrier kind and bounded active session candidates. They score each candidate's keyed screen pattern, preserve per-candidate raw correlation peaks and margins, and request attribution only when the top candidate and its cross-candidate separation are both clear; otherwise the server records `insufficient`.
- Worker candidate submission and trace-case completion now require the active, running `trace` job lease for the supplied case and worker ID. A worker token alone cannot write evidence to an unrelated or expired case; terminal trace job failures mark their associated cases failed.
- The worker-provided provenance binding must use the immutable profile selected by the leased trace job; a same-organization candidate from another profile is rejected before any threshold or decision processing.
- Screen trace processing retains the first and second deterministic candidate records when available. Rank one alone may request attribution after existing profile checks; rank two is always recorded as insufficient with its own raw correlation evidence.
- `watermarkProfiles:listActive` is available only to issuer, investigator, and administrator roles for selecting an active immutable profile during trace intake. It returns compatibility and detector metadata plus profile-owned thresholds, never key references or carrier secret material.
- `users:listIssuanceRecipients` is issuer/admin-only, scoped to the caller's organization, bounded to 100 active accounts, and returns only an opaque user ID, display name, and role for the issuance picker. It omits email and authentication material; issuance creation still re-checks membership and refuses disabled recipients.
- `onboarding:accessStatus`, `createOrganization`, and invitation functions bind every member to an authenticated WorkOS subject. A first authenticated administrator may create one organization; administrators create bounded, seven-day email-bound invitations only for viewer, issuer, or investigator roles. Claiming requires the matching authenticated email and can provision a subject only once. Cross-tenant membership lookup and invitation enumeration are not exposed.
- `watermarkProfiles:getActiveScreenProfile` is member-authorized and returns an active screen profile only if exactly one exists. Protected content fails closed for a missing or ambiguous registry, and the browser never selects a fallback profile or receives carrier keys.
- `dashboard:getSummary` is member-authorized and returns the caller's display context plus bounded counts: organization source documents and the caller's active web sessions for every role, plus bounded total/open trace-case counts for investigators and administrators. It exposes no trace handles, recipients, artifacts, or worker/profile secrets.
- The same dashboard summary returns only administrators' bounded job-state counts (queued, leased, running, retryable, failed). It does not expose job IDs, leases, inputs, outputs, errors, evidence, or worker identities.
- `GET /sign-in` starts the configured hosted WorkOS AuthKit interaction and `GET /sign-out` ends it. Neither accepts a user-controlled return target; neither returns a credential, modifies organization membership, or bypasses authenticated onboarding and role checks.
